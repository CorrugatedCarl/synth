## Files and ownership
1. `serum-core.js` — main-thread pure ES module (no DOM, importable in node): ALL constants (warp list, filter types + categories + Var labels, sub shapes, noise types, unison stack & detune modes, LFO/delay sync ladders, matrix sources, destinations with knob laws/ranges/defaults/display units), `defaultSerum()`, `normalizeSerum(s)`, `compileSerum(s, ctx)` → numeric engine patch, `defaultFx()`, `normalizeFx(fx)`, `compileFx(fx, ctx)`, curve renderers (LFO graph → table, envelope curve law, remap graph → table), display formatters `fmtParam(id, n)`.
2. `wt.js` — main-thread pure ES module: FFT, band-limited mip-map builder, original factory wavetable generators, WAV import/export incl. `clm ` chunk, Serum-syntax formula parser/evaluator (safe — NO eval/new Function), all editor operations (single/process/morph/add-remove/sort/import modes). `wtstore.js` — browser-only IndexedDB storage for user wavetables.
3. `serum-dsp.js` — AudioWorklet-side classic module with NO imports; attaches `globalThis.SerumDSP = { SerumVoice, SFilter, storeWT, begin, fxMods, ... }`. Consumes ONLY the compiled numeric patch from compileSerum.
4. `fx-dsp.js` — AudioWorklet-side, NO imports; attaches `globalThis.FXDSP = { FXRack }`; uses `globalThis.SerumDSP.SFilter` for the Filter module (load order serum-dsp → fx-dsp → engine).
5. `serum-ui.js` (+ `wtedit.js` wavetable editor, `graph.js` shared drawable-curve editor for LFO / envelope display / remap graphs) — the Serum instrument panel (OSC / FX / MATRIX / GLOBAL pages), drag-to-modulate, halos, right-click menus.
6. `fx-ui.js` — FX rack UI, used both for every track's FX tab and inside Serum's FX page.
7. Integration (later, by a separate engineer): engine.js, models.js, main.js, index.html, style.css.

## Engine host contract (engine.js will provide)
- SynthProcessor with `p.engine === 'serum'` creates voices `new SerumDSP.SerumVoice(proc, i)`. A voice implements `apply(p)`, `noteOn(n, vel01, legato, glc)`, `noteOff()`, `kill()`, `render(bufL, bufR, N)` (ADDS into OS-rate stereo buffers), and fields `active, gate, note, stamp, sus, det, vel`. Existing allocation (poly/mono/legato/sustain/steal) stays in engine.js; Serum's portamento law (time, curve, always/scaled) is implemented by the voice itself (engine passes `legato` and a glide coefficient it may ignore).
- proc provides: `fs` (OS rate), `base`, `OS`, `CH` (4*OS frames per control chunk), `bendRaw` (−1..1), `wheel`, `at` (0..1), `p` (patch), `bpm` (song tempo), `songBeat()` (current song position in beats, or null when stopped) for host-anchored LFOs, `held` (mono note stack).
- Each render span: engine calls `SerumDSP.begin(proc, N)` once before voices (global/'free' LFOs, chaos, smoothing of macros/perf sources), then voices, then `SerumDSP.fxMods(proc)` → Float64Array of mono modulation offsets for FX destinations (from the most recently triggered voice), passed to `FXRack.setMods()`.
- Wavetables: message `{t:'wt', id, frames, levels:[{len, harm, data: Float32Array(frames*len)}]}` (data transferred) → `SerumDSP.storeWT(id, entry)` into a global Map shared by all processors of the context. `processorOptions.wts` = array of the same for OfflineAudioContext bounces. Missing table → that oscillator is silent until it arrives.
- Stereo: engine gives Serum voices two OS-rate buffers and decimates both channels.
- FX rack: every processor owns `new FXDSP.FXRack(base)`; `p.fx` (compiled by compileFx, present for EVERY model) configures it; it runs on the stereo base-rate signal after the model's built-in chorus/ensemble and before the limiter. FXRack must be fully bypass-cheap when all modules are off.
- Tempo: `p.bpm` also given in every patch.

## Data
- Serum track: `track.vals = { s: <serum state> }` (model id 'serum'). FX: `track.fx = <fx state>` for EVERY track (any model). User wavetables in IndexedDB (wtstore.js) and embedded (base64 Float32 frames) in saved project files for portability.
- Presets: `{ name, v: { s: <state> }, fx?: <fx state> }`.

## Quality bar
- DSP: 64-bit math, band-limited wavetable playback via mip-maps (choose level by pitch with headroom for the OS rate), smooth frame interpolation where Serum interpolates, no zipper (smooth modulated params per sample or per chunk with interpolation), no clicks on voice steal, CPU-conscious (unison 16 × 2 osc × 8+ voices must be feasible at 2x: shared per-chunk computations, typed arrays, no per-sample allocation, monomorphic hot loops).
- UI: polished dark Serum-like layout (original artwork, not Xfer's), responsive, keyboard/touch accessible, matches site code style (2-space indent, semicolons, single quotes).
