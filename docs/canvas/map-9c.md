## 1. Per module: what RM says, and what a contract is missing

(RM tags: [R] published/bench, [R?] secondary/emulation, [C] our choice. "d" = documented width; "?" = RM has no width.)

### 901 / 901A / 901B / 901C (RM:156-160; levels :48-49; sets :114-116; split :65-68; law :248; targets :262-263; conflict :325)
- **901** (1965, "VCO + LFO"), **3 MU d**: = a 901A + 901B on one panel. Controls: Fixed Voltage Control (pitch, **−5 … +6 oct**), Frequency Range (**Lo, 32′, 16′, 8′, 4′, 2′**),
  fine tune (±1 oct; emu "0/1/2"), pulse width; **3 summed control inputs**; **4 fixed outputs** (sine, sawtooth, triangle, pulse) + **4 variable outputs** (0 … 0.5 V).
  Span 0.1 Hz … 15 kHz (manual); bench unit 1.7 Hz … 31.7 kHz, Lo 35 mHz … 70 Hz, least distortion ≈ 5 kHz, pulse width 47.8 … 91.5 % (one unit), tracking claimed 5 oct but ≈ 2
  measured, strong temperature drift [R MS-901 / JD-901]. Circuit: UJT ramp core, triangle by a 2-transistor circuit, pulse by comparator, sine by a diode shaper (RM:156).
- **901A** (1 MU d): precision 1 V/oct sum + pulse-width control; 3 control jacks; "Fixed Voltage Control, range, fine"; drives **3** 901Bs (MS) or **12** (JD manual quote) — RM:157,
  conflict row RM:325 ("3 per driver in the UI; allow up to 12 [C]"). Exponential converter lives in the **901A** (output doubles per octave), the **901B ramp is linear in it**, so
  the 901B vernier detune is **fixed Hz** (RM:65-68, :248; [R? ZB-EVO]) — unlike the 921B, whose vernier acts before its own converter (MD:460 `kv = … + fq/6`, then `ex2` at MD:485).
- **901B** (1 MU d): Range (Lo + 5), frequency vernier (≈ ±1 oct + a major third; emu), 4 fixed + 4 attenuated outputs; no pulse-width of its own (set on the 901A); tracking and
  ramp-symmetry trimmers (RM:158). Levels: manual says all four fixed outputs **0.5 V RMS / 600 Ω**; one bench 901B reads ramp 1.73 Vpp, triangle **2.25**, sine 1.41, 50 % pulse **2.4** Vpp
  (RM:48-49; T-OSC2 :263 adopts the bench set as default). Stage 9 modelled the *921B* at saw 1.732 / sine 1.41 / tri 1.13 / rect 1.70 Vpp (MD:56, RM:380) — not these.
- **901C** (1967, hand-wired, 15 made; width **?**): patched to a 901-family output; controls amplitude and polarity so the oscillator becomes a CV source; two CV outputs 180° apart (RM:159).
- **Missing for a contract**: (a) which controls sit on the 901A vs the 901B (RM rows :157/:158 both list a range and a fine/vernier); (b) the **vernier's Hz scale** (fixed Hz — how many?)
  and the Lo range's law (the 11-octave Fixed Voltage span = 35 mHz … 70 Hz is consistent [mine: 2^11 = 2048, 70/0.035 = 2000]); (c) how many attenuator pots the 4 variable outputs have (one each? RM silent);
  (d) the pulse-width law and range (RM gives only one unit's 47.8-91.5 %; the 921's is 10-90 % + 10 %/V, MC:117, RM:383); whether the 901A has width-CV jacks (RM: "3 control jacks" only);
  (e) any sync input (none documented); (f) **901C**: jacks, knobs, width, ranges — nothing beyond one sentence; (g) fan-out 3 vs 12 (`link.max`); (h) fixed-output level set (0.5 V RMS spec vs bench levels);
  (i) the 901's sine is a diode shaper (not ideal) — purity/shape numbers absent; the 921 model uses ideal polyBLEP waveforms (MD:300-354).

### 904C (RM:181; set :125; PAT fig. 3 :239; T-VCF3 :268; §8 none)
- "Filter coupler (1965; omitted from the 1970s systems)", width **?**. Mode switch **Band Reject / Off / Band Pass**; Center Frequency; Bandwidth (≤ 3 oct emu); CV jacks for centre and bandwidth.
  Joins a 904A and 904B **in series (band-pass) or parallel (band-reject) internally**; "the other 904s must be centred"; one control moves both cutoffs together, the other in opposite directions
  (the second CV "inverted for one filter": RM:239).
- **Missing**: its own signal jacks (where does the parallel *sum* appear? the series output is the 904B's — RM silent); the centre/bandwidth→cutoff laws (octave scale, ±? per volt, the knob's range);
  whether it needs its pair to be a particular 904A/904B (and how many couplers there can be); the 3-position switch's exact wiring; the width.

### 905 (RM:185; set :126; §4.4 :257)
- Reverb, 1965, width **?**. "A single **wet / dry** control; in, out; spring tank (Gibbs); output phase-inverted; minimal circuit" [R MS-905; R? CH-905]. RM:257: "any plausible spring/allpass model is [C]".
- **Missing**: everything quantitative — decay time, number of springs, dispersion/"boing", the wet/dry law (crossfade? is dry also inverted?), input headroom/overload, the width. Fully [C]; no listening reference exists
  (memory: user has no hands-on reference for vintage machines — build on measured targets; CLAUDE.md "Working rules"). The word "Gibbs" is a maker name: keep it off faces/tiles (cv-panel.js:73 MAKERS rule).

### 912 (RM:195; set :131; §1.3 :55; §8 :329; T-ENVF1 :274)
- Envelope follower, width **?**. Response (short / medium / long); Threshold (comparator); Signal in; Control out (**normalled to the comparator input**); S-trigger out (a 1/4″ jack, externally pulled up).
  Control out: in 31 mV → 2.4 V, 127 mV → 3.5, 500 mV → 4.5, 1 V → 5.0, 2 V → 5.5, 4 V → 6.0 (measured within 0.2 V); **≈ 0.5 V per amplitude doubling (log)**; calibrated at 250 Hz, 500 mV p-p; takes up to 4 V p-p;
  response 0.01 … 0.1 s (**emu only**); comparator thresholds with hysteresis **320 mV/120 mV, 2.88 V/0.2 V, 5.7 V/0.3 V**; 3 trimmers, two interact.
- [mine] The table + RM:55 ("3 … 6 V for 63 mV … 4 V p-p") fit one law, **V = 5 + 0.5·log2(Vpp / 1 V)** (31 mV → 2.49, 63 mV → 3.0, 127 mV → 3.51, 500 mV → 4.50, 1 → 5.0, 2 → 5.5, 4 → 6.0), and "500 mV p-p" is the calibration — so the input unit is **peak-to-peak**.
- **Missing**: detector type (peak / average / RMS) and attack vs release times (only the emu's 0.01 … 0.1 s for three positions); which Threshold knob positions the three hysteresis pairs belong to (the knob's law); whether the
  comparator input has its own jack (RM:195 says only "normalled", which implies one; MS-912 is RM's source); behaviour below 31 mV (floor); width.

### 984 (RM:196; set :133; §3.4; "6401" note RM:15-16; T-MIX1 :275)
- Four-channel mixer (1965), width **?**. **4 inputs × 4 output busses (a 4 × 4 level matrix), a master per bus, Bass and Treble (flat at 5); AC-coupled, audio only**; max gain **1.25** through any channel (tone centred); PCB per two channels.
- **Missing**: the number of jacks (4 in / 4 out assumed), the taper of the 16 + 4 pots, whether bass/treble is global or per bus (22 knobs vs 16 + 4 + 8), the tone corner frequencies and ± dB range (no number anywhere),
  the AC-coupling corner (the 921B's AC input uses a 10 Hz one-pole: MD:457, I9:236), polarity (the 902's/905's inversions are stated; the 984's is not), width. (The "6401" is not a module: RM:15-16.)

### CP3 (RM:198, :221, rails :41, T-MIX1 :275; sets :136 "CP3×4" for IIIc/IIIp)
- Original CP3 mixer: 4 inputs, + and − outputs, master gain, click filter, 4 routing switches, 3 multiples, trunks; audio PCB 2× gain; CV PCB scale 1.0 … 1.08×; **runs on +12 / −6 V and clips asymmetrically (negative half first, ≈ 5 V)**; the CP3A has ±15 V and

## 3. Specific engine questions

### 3a. The 901 family vs the 921 / 921A / 921B split
- **Existing pattern**: 921 = self-contained (own converter; M921 MD:361, no link). 921A = driver, **no front output**, link outputs `V_drv = f1+f2+f3+kv` and width offset `(pw−50)/100 + 0.1(w1+w2)` (MD:427-437; `xout: 2` MD:122); 921B has `xin: 2` (MD:127) reading `I[3], I[4]` after its 3 real inputs (MD:471) and does its **own `ex2` per sample** (MD:485).
  Link is data: `link: { to:'921a', max:3 }` (MC:136) ↔ `LINK['921b'] = { from:'921a', def:[0,0] }` (MD:271); the evaluator treats it as an edge driver→driven (PD header :48-52, famTable PD:102-105, wiring PD:252-259) — **keyed per driven type, `nLO` per driver type, so a second link pair is supported by the evaluator** (PD:103-105).
  patch-core: `drv` per module, `setDriver`, `addModule` auto-driver, `loadPreset`/`makeSet` shedding (PC:142-147, 423-433, 476-483; MC:510, 517) — all by `T.link.to`, **one link type per driver type** (`Object.values(fam.types).find(T => T.link && T.link.to === …)`, PC:480; MC:517): a 901A↔901B pair is fine, the 901A cannot also drive another linked type.
- **Mapping 901A/901B onto it**: new `link: { to:'901a', max:3|12 }`, `LINK['901b']`, 901A `xout` = its link-def length, 901B `xin`. **What differs is the law across the link**: the 921A passes the 1 V/oct *sum* (log domain) and the 921B converts; RM:65-68/:248 says the 901A converts and the 901B is *linear* in it with a Hz-fixed vernier — so the 901A's link output would carry the exponentiated control (one `ex2` per driver per sample instead of one per 921B [mine: a cost saving]) and the 901B adds its vernier in the linear domain. The combined **901** (3 MU) is a self-contained class like the 921, not a link (same split as 921 vs 921A+B).
- **Reuse / do-not-edit**: `Osc` (MD:307-354, shared by 921/921B), `ex2`, `base`, `drift`, `insAcc` are ref-9/ref-9b-frozen code (I9b:34-36): a 901 may instantiate `Osc` but cannot change it; its own level constants (tri 2.25 / pulse 2.4 Vpp vs `AT`/`AR` MD:56) go in new constants. Warm-up: the 901B is warmed driven + undriven automatically (EN:1581).
- Also: `max` 3 vs 12 changes the "driver sheds unbound highest-first" rule's reach (PC:480-483) and warm part splitting (EN:1654 "a linked type in its driver's part").

### 3b. 905 — is there reusable spring/reverb code?
- **fx-dsp.js**: `Reverb` (Dattorro plate PL_*, Hall = 4 diffusers → 8-line Householder FDN HL_*) at fx-dsp.js:1166-1182, S2 `Rev2` + tanks `RevVintage/Nitrous/Basin` (fx-mods2.js:1019, 1094) — **none is a spring**, all live *inside* the FX IIFE; `FXDSP` exports only `FXRack` etc. (fx-dsp.js:3420-3423) — no `Reverb` is reachable. They share one Float32 pool/topology protocol with the rack (fx-dsp.js:1702-1714). MD is a standalone classic worklet script that "reads no other script's global at load" (MD:3-6): nothing can be shared without copying. **Must not be reused as the 905**: wrong topology, the FX rack's own frozen sound (golden-fx).
- **A spring character already exists in the repo, offline only**: smpgen.js:466-486 `springTrain64` / `spring()` — echo trains at 25 / 31 / 37 ms (R ×1.03), RT60 2.5 s, **120 first-order allpasses a = 0.6** (R 0.62), 3 s; the Convolve library item "Weird/Spring" (smpgen.js:185, serum-core.js:4796; comment smpgen.js:44-45). It is a main-thread/IR generator (no AudioWorklet reuse); its *numbers* are our own [C] and a 905 could take the same character for consistency.
- Engine facts that shape it: per-OS-sample module code, state in typed arrays allocated in the constructor (allocation is allowed in `graph()` only, PD header :21; modules are built there). A 120-stage chain keeps state in arrays, **not "registers"** — the 907A/914 register-fused form (MD:637-643, 955) reloads state each `run` call, which is poor when the module sits in a loop step (`run(sec, i, 1)`, PD:58-62; loop members cost 10-18 ns/sample: I9b:895-896). `flush()` every 32nd chunk must clear the chain's subnormals (MD base contract :26). The I9 decision **dropped a base-rate 907A** ("as dear or dearer, ≈ 1.5 ms latency, can't be a loop member", I9:1042-1043); a base-rate spring would face the same trade.
- Honest status: **every number is [C]** (RM:257); no research target to test against except "wet/dry, inverted".

### 3c. 912 — envelope follower
- Templates in the table: the **961 AUDIO→V comparator** with hysteresis (`θ` on, `θ/2` off; MD:1246-1248, MC law `th961` MC:69) and the controller's GATE IN→S-TRIG converter (+1.5/+1.0 V, I9:233); S out = a `sig: 's'` jack read as `> 0.5` (MD header :37-40; 911 reads S as 1/0, I9:232). The 911's RC-toward-target stage shapes exist (MD:718-756).
- **Normal**: `norm` may name an output of another section (CP35: `i1` ← `p6`, MC:265, MD:236; I9b:929-930), so "control out normalled to the comparator input" = a comparator-in jack in a second section with `norm: <control out id>`; sections break the cycle (a section's outputs depend on its own inputs only: MC:19). Whether the comparator input is a jack is the RM gap in §1.
- Law candidate [mine]: log of the detected amplitude, `V = 5 + 0.5·log2(Vpp)` (§1), an exact `log2` per sample is expensive — the repo's `ex2` is a *table × polynomial* (MD:65-70); a log needs its own approximation (new code, tested like `ex2`'s ≤ 1.5e-4 cent claim, RM:379).

### 3d. 984 — matrix mixer vs the existing mixers / routing panels
- Existing: the controller MIX (4 in, MIX ±; MC:313-314) and **CP3A** mix (MC:250, MD:1398-1406): one weighted sum, `mo`/`mn`, outputs gated by `om` (a read-only-when-cabled mask: MD:1402). There is **no module with more than one mixed bus**. The routing panels (992/993/CP3A/CP4A/CP2) are **hidden CV/trigger bus rows** behind lit switches (PC:558-633, I9b:165-199), never audio and never drawn — not the 984's model.
- A 4 × 4 matrix must be **one section**: a jack belongs to one section and "a section's outputs depend only on its own inputs" (MC:19), so four sections could not share the four inputs. Four outputs, 16 + 4 + 2 params fit every limit (≤ 48 params: moog-core.test:70; ≤ 30 outputs and ≤ 16 sections per type: I9b:74); unread outputs cost nothing via `om` (as the CP3A's `a`/`b` flags). Patched back to its own input it becomes a one-member loop step (the 960's 0.0035 in a loop vs 0.001 alone: I9b §12 V9c table).
- Panel size: 22 controls + 8 jacks — within the DOM budget as a lite face (3 painted per control: 67 + 8 + bar; a 1 MU module ≤ 90, 914 ≤ 100, a console panel ≤ 90: I9b:536). The face is wide but its width is unknown (RM).

### 3e. 904C — a coupler between a 904A and a 904B as separate patch nodes
- 904A = `M904A` (4-pole ladder + regeneration; one section, MD:583-635); 904B = `M904B` (four buffered one-pole high-passes, no feedback; MD:906-946); both are **separate modules with their own jacks**, summing 3 CV inputs, and every pairing is a user patch.
- Three ways the existing machinery allows a coupler, none decided by RM: (i) **self-contained** (the 904C contains its own LP ladder + HP, composed from the same maths; independent of the user's 904A/B; the 921-style); (ii) **bus rows** (PC:558-633): CV rows from the coupler to `904a#=.c3` / `904b#=.c3` (the `#=` end binds the k-th 904C to the k-th 904A/B: BUS_RE PC:567; the 992/CP4A already route into `904b#1.c3` / `904a#1.c3`, MC:230, 259) and audio rows `904a#=.out → .pa` (rear input) etc., the coupler summing its parallel rear inputs to a front output; its CV section and signal section must be **separate sections** (else a cycle: coupler → 904A.c3 → 904A.out → coupler);
  (iii) a `link` — **not suitable**: a link is driver→driven with exactly one driver (`drv` names one module: PC:142-147).
- Limits of (ii): a bus row's switch test is **"≠ 0" per listed switch** (PC:603), so a 3-position Mode (Band Reject / Off / Band Pass) cannot select between two mutually exclusive row sets without two switches or a patch-core extension (allowed if existing payloads stay byte-identical; ref-P/ref-9-core pins PC:1151-1152, :965-987); rows hold only out→in pairs of one plug kind (PC:606); a row into a jack that also has a cord *adds* (inputs sum, PD header :71-72); duplicates of an existing (source, input) pair are skipped (PC:586-611).

## 6. Summary (10 lines)
1. 10 types: 901, 901A, 901B, 901C, 904C, 905, 912, 984, 991, CP3. Widths are documented only for 901 (3 MU) and 901A/901B (1 MU); every other width is "?" (RM:156-159, 181-198, §8 :331).
