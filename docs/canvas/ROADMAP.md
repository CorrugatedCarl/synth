# SYNTH Canvas: roadmap and status

This is the living tracker for the canvas redesign. The design is [SPEC-canvas.md](SPEC-canvas.md) (with the user's decisions at its end) and the plain-language version is [SUMMARY.md](SUMMARY.md). This file records **where we are**, **every change the user's feedback has made to the plan**, and **what comes next**. Update it at the end of every stage.

- **Branch:** `canvas` of CorrugatedCarl/synth. `main` stays live at synth.domlavin.com and is never merged into or overwritten by canvas work ("in case I regret it").
- **Preview:** canvas.domlavin.com (repo CorrugatedCarl/synth-canvas), deployed with `tools/deploy-canvas.sh` from the committed `canvas` HEAD. The canvas site has its own storage and starts fresh.
- **Every stage:** contract → parallel builders → integrate → multi-dimension review with adversarial verification → fixes → every test file run one at a time → deploy → the user tries it on the iPad → feedback folded in before the next stage. (Stages 1c and 1d ran lean while usage was limited; the user asked for the full process again from 1e.)

## Gates

- **iPad bench (before 1d): DONE 2026-10-18** — recorded in `tests/bench.json` `"ipad"` (iPad Pro, iPadOS 26.6, Chrome for iOS/WebKit). Device factor vs the M4 Max node reference ≈ 0.67–1.00 (median ≈ 0.83): every row well inside its iPad target. WebKit's 1 ms timer quantizes the 'worst quantum' columns (0.375 = one tick), so 1d's iPad gate uses the row loads. To re-run: the user opens `https://canvas.domlavin.com/tests/bench.html` in Safari on the iPad (plugged in, other apps closed), taps **Run 5 passes**, then **Copy results**, and pastes them; they go into `tests/bench.json` under `"ipad"`. Stage 1d's performance gates compare against it.
- **iPad bench (after 1d): DONE 2026-10-18** — `"ipad1d"` (same iPad, Safari, build 8abcd204b514): every row within 5 % of `"ipad"` and inside its target; 1d passes. Later runs (1e, 2b, 5) compare against `"ipad1d"`. A run is valid only when its JSON says `"stale": false` and names the deployed build: a browser whose service worker has not applied the update measures the previous build (the first attempt in Chrome did).
- **Sound:** every stage keeps the golden tests bit-identical for unchanged sounds; DSP files only change from 1d on.
- **Stage 1e gates (2026-10-18, IMPL-1e §8.2 / §8.4):** goldens bit-identical in legacy, graph and processorOptions form; canonical message stream unchanged; V8 and JavaScriptCore A/B vs the 1d engine within 1.3 % per row; new bench row r (Prophet-5 + Juno-60 + Serum + a 3-effect panel) 0.10 on the Mac (target 0.15; iPad target 0.12).

## Standing preferences (from earlier feedback)

- Native page zoom only; never an app-owned page zoom or viewport rewriting. Canvas zoom is a transform of the world layer.
- Two-finger pan/pinch always wins over single-finger presses (`gesture.js`), and must never slow native scrolling.
- Trays slide and collapse; the keyboard tray is resizable/hideable.
- Agents never search outside the project folder and scratchpad (macOS privacy prompts).
- Test memory safety: never the full suite in parallel agents; one test file at a time; never fake-DOM nodes in `assert.*`.

## Implementation decisions taken during stages (user may revisit)

- **Sources views (2026-10-19, was the 1c "Hardware \| Simple" switch):** the tray's dropdown lists views from data (cv-tray `SRC_VIEWS`: an ordered list of {id, label, tip, layout, note, sections}; a section shows synth tiles by a model filter, the Modulators, or a heading with a one-line note), so later families — **Drums** (drum machines) and **Controllers** (the pad grid) — are one more entry each, not a new tray. Hardware and Simple differ only in the layout a classic synth comes in (a tap on the current synth's tile still switches its layout both ways); Serum keeps the last of the two (Serum has no hardware panel). Tiles and sections outside the view are `hidden`, not removed: a drop, a tap, `setPlaced` and the cost labels work in any view. Serum parts / Note tools show only their heading and "arrive in …" until those stages; the Modulators no longer appear under Hardware / Simple. A stored view the app does not know opens Hardware.
- **Performance modulators (2a):** the Mod list opens from ⋯ → "Modulation list…" on a Serum or a modulator module (not a toolbar button); a cable's long-press menu has Edit…, Bypass and Disconnect, the amount lives in the inspector; the modulator column sits left of the instruments at x −320; a dropped modulator lands where dropped, a tap places it in its column slot; the amount badge reads ±/∓ for bipolar amounts; preset-row edits follow the Serum's knob-tweak policy (no project undo step); "Save with preset" undo/redo moves only that row's slot and never reverts other Serum edits; a canvas drop follows the Serum's "Limit mod depth on drop" setting.

- **Hardware panels (1b+):** 2 px per mm; module sizes rounded up to the 32 px grid. Controls a synth has beside its keyboard (e.g. Minimoog DECAY, CS-80 / Jupiter-8 portamento, Juno-60 octave transpose, Solina ensemble) are drawn on their real side plate, not moved to the extras strip. Hardware controls we don't emulate are drawn dimmed ("not emulated"). The ⋯ menu gained Save / Delete / Init sound and the chip gained ◀ ▶ preset arrows (a hardware face has no preset plate).
- **Controls sleep below 50 % zoom:** without cards, a one-finger pan of a zoomed-out canvas would otherwise turn whatever knob it lands on, so below 50 % a press inside a module pans unless the module was double-tapped. Nothing visible changes.
- **Making room:** when a wider instrument would overlap, the FX and OUT modules move right (never pulled back left).
- **One synth per track again (1f):** the 1e paragraph below describes the withdrawn UI (kept for milestone 3). Since 1f: a Sources drop anywhere on the canvas, a tap, or ⋯ → Replace with… replaces the track's instrument (one step, "Replaced X with Y · tap to undo"); an Effects-tray effect tapped or dropped anywhere on the canvas goes into the track's panel (a Serum's own FX); every cable is read-only; the safeguard badge ("OS 4→2") stays. Loading a project whose track held several instruments, or a shape the UI can no longer make, splits it (cv-migrate `splitTracks`): the first instrument that sounded keeps the track, each other one becomes "<track> · <model>" with the notes and the panel it fed (a shared panel copied; a classic straight into OUT gets an empty panel: same sound); a Serum heard through a panel takes the panel's effects when it has none of its own (same sound); an instrument that did not sound comes in muted; zones / solo / cable levels / unconnected panels are dropped — and one notice for the project lists, per track, what changed. Before the first save of a split autosave the stored project is kept once, as it was, under `synth.project.pre1f` (IndexedDB kv `synthc.project.pre1f`; never overwritten; recover by hand, HANDOVER §6). The key-zone pill is gone (the default camera no longer frames room for it).
- **Several synths (1e, UI withdrawn in 1f):** a Sources tile dropped on empty canvas adds an instrument (auto-cabled to the panel with the most instruments, else OUT); dropped on an instrument's top bar it replaces that one; a tap replaces the current instrument (the last one tapped). Notes go to every powered instrument (key zones on the pill at the module's left edge, or ⋯ → Key zone…). An effect added to an existing panel is not an undo step (the rack's "+" rule); new panels, cables, power, zones, Make primary, Duplicate and Delete are one step each. The Effects tray never closes during a drag. A Serum's internal jacks are not patchable (its external jack is its own FX's output); dropping another instrument's output on a Serum's own FX is refused with a one-tap "Make a shared panel". Pressing a cable pans; a tap selects it (× to disconnect). The default camera keeps the key-zone pill clear of the Sources rail, so a lone Minimoog opens at ≈ 94 % instead of 100 % on a 1440 px window (**the user may prefer the pill inside the module**). The minimap and toolbar box is kept clear of module bars and the minimap hides during drags. Save as classic project lists zones, cable levels, solo and silent instruments among what main cannot hold. ⚙ → Measure this device stores a CPU factor (`synth.cv.devFactor`) that scales the tile cost labels; on touch devices a 4th instrument warns and a second heavy Serum asks first.
